# qwen-dap-mcp v0.13.0

v0.13 adds first-class upstream LLVM `lldb-dap` support while preserving CodeLLDB compatibility and the compact default agent toolset.

## Upstream LLVM lldb-dap

The bridge now has a dedicated `lldb-dap` adapter profile instead of treating upstream LLDB as a CodeLLDB alias. It supports:

- explicit adapter paths and `LLDB_DAP_PATH`,
- canonical/versioned PATH binaries and common LLVM toolchain directories,
- `LLVM_HOME` and macOS `xcrun --find lldb-dap`,
- live launch and authorized PID attach,
- read-only core-file inspection through upstream DAP `attach` + `coreFile`,
- high-level diagnosis and bounded verification through `debug_this_crash(mode="lldb-dap")`.

Existing CodeLLDB paths remain available and remain the compatibility default for existing CodeLLDB-specific dump workflows.

See [lldb-dap.md](lldb-dap.md).

## Fatal signal semantics

Upstream lldb-dap can surface synchronous POSIX failures such as `SIGSEGV` as DAP exceptions with `breakMode="always"`. v0.13 distinguishes explicit fatal signal families from generic configured/first-chance exceptions so genuine crash stops remain crash-likely without weakening the conservative verification model.

`crashLikely` is diagnostic evidence, not proof of a successful fix. A fix still requires completion of the intended reproduction and evidence comparison.

## Compact MCP surface preserved

The default `agent` toolset still exposes only the nine high-level tools. Manual `lldb-dap` discovery/start/launch/attach helpers are available only with:

```text
QWEN_DAP_MCP_TOOLSET=full
```

## Real validation

The Linux smoke workflow installs distribution LLDB, discovers the real adapter without a hard-coded major version, compiles native C++ fixtures, and validates:

- DAP initialization over stdio,
- source breakpoints,
- stack frames, locals, registers, modules and disassembly,
- expression evaluation,
- the complete high-level `debug_this_crash(mode="lldb-dap")` crash-diagnosis path against an intentional native SIGSEGV.

Normal Node.js 20/22 CI, Crash Lab, extension packaging, and container validation remain part of the release gates.
